PROJECT 01 7TH SEMESTER · PCB DESIGN · AUTOMOTIVE TESTING

ECU power management
& testing system

The main goal set by International Motors Mexico was to create a system that controls power to four ECUs, monitors their CAN messages and electrical behaviour, and runs automated tests.

I was responsible for the circuit design, PCB layout, component calculations, assembly and soldering: one replaceable board per ECU, with MOSFET switching for fast, repeated operation without contact wear. The project was selected for ExpoIngenierías and demonstrated live with International ECUs.

Validation included extended operation, repeated switching, CAN reception from real ECUs and sensor readings checked against lab instruments. I used an oscilloscope to measure switching response times. Safety features included a main fuse, shutdown on over-voltage and a fail-safe if the computer disconnected. Hardware and documentation were handed over to International. Due to their confidentiality policy, ECU-specific CAN messages, VISA command sequences and detailed test results cannot be shown. During my seventh semester, I worked with International Motors Mexico on a system for controlling power to four ECUs, monitoring their CAN messages and electrical behaviour, and running automated tests. Weekly meetings with two International engineers helped guide the development through progress reviews and technical feedback. The prototype used one replaceable board per ECU, with independent control of its battery, accessory and ignition lines.

I was responsible for the circuit design, PCB layout, component calculations, assembly and soldering. I calculated resistor values and PCB trace widths, selected protective components, and chose MOSFET switching to support fast, repeated operation without mechanical contact wear. I also integrated measurement sensors and output-status LEDs. The system combined ESP32 firmware written in MicroPython with a Python computer interface developed mainly by my teammates.

A tight budget, without university funding, shaped the hardware choices. The prototype used through-hole components and separate modules for CAN communication and current and voltage sensing. I also proposed a smaller, integrated PCB combining the ESP32, CAN circuitry and measurement chips on one board. This alternative remained a design for future development and was not manufactured.

A major part of my work involved thinking through possible failure scenarios and testing the system’s response. Validation included extended operation, repeated switching, receiving CAN messages from real ECUs, and checking sensor readings against laboratory instruments. I used an oscilloscope to measure switching response times. The system also supported text-based test sequences, a main fuse, shutdown when monitored voltage exceeded a set limit, and a fail-safe response if the computer disconnected. Improvements to wiring, connectors and future expansion were documented for later versions.

The project was selected for ExpoIngenías, where it was demonstrated live using International ECUs and received positive feedback from professors and judges. The hardware and documentation were handed over to International, whose engineers expressed interest in continuing its development.

Tools used: KiCad · ESP32 · Python / MicroPython · CAN communication · VISA communication · PCB assembly and soldering · Oscilloscope · Hardware validation

Embedded vision &
robot control platform

A tracked robot built for a master’s research project on TinyML-based path following. I developed the hardware and software infrastructure for testing future models.

A control engineering professor invited me to develop a robotic platform for a master’s research project on TinyML-based path following. My task was to build the hardware and software infrastructure needed to test future models. I developed a tracked, differential-drive robot using an STM32 NUCLEO-F446RE and Raspberry Pi 5, combining motion control, orientation sensing, camera capture and a browser-based interface.

I adapted an existing Madgwick sensor-fusion implementation for the MPU9250 and implemented DMA-based IMU acquisition to reduce the processor’s involvement in data transfers. I reused and refined my earlier calibration routine, corrected sensor readings and applied filtering to reduce noise and orientation drift. I also handled wheel-encoder acquisition, implemented PI motor control, and added fail-safe behaviour.

On the Raspberry Pi, I integrated a Pi Camera and OpenCV, adjusting image resolution, frame rate and noise reduction while preserving the colour information required by the planned models. I built a local-network web interface that displayed live video and IMU readings, alongside buttons for testing the robot’s movement from a phone or computer.

I packaged the Raspberry Pi applications and their dependencies using Docker, allowing the software stack to launch with one command and making the setup easier to reproduce and restart. At handover, sensing, video streaming, browser controls and robot movement were working. The platform was prepared for the master’s student’s next stage of model integration; developing and deploying those models was outside my contribution.

Tools used: STM32 NUCLEO-F446RE · Raspberry Pi 5 · MPU9250 · Madgwick sensor fusion · DMA · Encoders · PI control · L298N · Pi Camera · OpenCV · Docker

PROJECT 04 5TH SEMESTER · EMBEDDED · MOTOR CONTROL

Autonomous
tractor-inspired robot

Control software and electronics for a robot that drives a square route over rough, gapped tiles and returns to its start point, guided by John Deere engineers.

Using an STM32, I implemented PI speed control with four wheel encoders and a PID heading controller. I modelled the motors with PRBS test inputs, tuned the controllers in MATLAB and wrote an MPU9250 calibration routine.

I developed the control software and integrated the electronics for a tractor-inspired robot during my 5th-semester Industrial Automation course, under the guidance of John Deere engineers. The challenge was to follow a square route of approximately 15 m per side across rough tiles with gaps, then return to the starting point and direction. The robot met the required 15–30 cm return tolerance. I focused on reliable movement and automatic heading correction rather than speed.

Using an STM32F103C8T6, I implemented PI speed control with feedback from four wheel encoders and a PID controller to correct the robot’s heading after disturbances. I used PRBS test inputs to record the motors’ response, build a plant model, and check it against separate data. I then used MATLAB’s PID tuning tools to tune the PI control.

I developed a calibration routine for the MPU9250 that included keeping the robot still and rotating it in figure-eight movements. I corrected the raw sensor readings, applied low-pass filtering, and adjusted sensor weights between straight sections and turns. Gyroscope and magnetometer readings supported heading control, while acceleration and encoder data helped estimate travel distance.

I also made molds and cast silicone wheels to improve grip and reduce bouncing. The robot used a laser-cut acrylic base, a 3D-printed tractor-style body, L298N motor drivers and rechargeable 18650 batteries, with separate supplies for the control electronics and motors. I tested and refined the system on the course surface, including its ability to straighten its heading after being pushed.

Tools used: STM32 · C · MPU9250 · MATLAB · System identification · PRBS · PI/PID control · Encoders · L298N · Silicone molding

PROJECT 05 4TH SEMESTER · MECHANICAL DESIGN · MOTION CONTROL

Mini mechatronic
foosball table

I designed and built a mini foosball robot during my 4th-semester Implementation of Mechatronic Systems course, finishing second out of more than 15 designs in the class tournament.

My custom gear system moved the player faster than direct-drive stepper designs, and a 12 V solenoid let the robot move and strike at the same time. I designed the CAD parts and MDF case, and built a joystick controller, goal counter, LCD scoreboard and a custom AC–DC power supply.

My custom gear system achieved faster player movement than direct-drive stepper designs, while a PI controller made movement smoother. I used a constant PWM signal from the Arduino's hardware timer to control the stepper motor through a TMC2209 driver, allowing the robot to move and strike at the same time using a 12 V solenoid.

I designed the mechanical parts in CAD, printed them in PLA, and designed and cut the MDF case. I also built a handheld controller with a joystick and shooting button, added a distance sensor to count goals, and used a 16x2 LCD to display the score and game information. Two limit switches kept the player within its travel range. I tested and refined movement, shooting and goal detection by adjusting the hardware and code.

For extra credit, I designed and built an AC-DC power supply with a 12 V output and a step-down converter to 5 V. Its extra power capacity allowed me to reuse it in later projects.

Tools used: Arduino Uno · CAD · 3D printing · MDF fabrication · Gear design · PI control · Power electronics

PROJECT 06 MEASUREMENT · SIGNAL ANALYSIS

AC frequency
measurement system

Arduino · Python · Signal Analysis · Mechanical Design

I designed and built this AC frequency measurement system for my Mechatronic Integration course, combining Arduino, Python and mechanical design for power-supply monitoring.

The system monitored frequency changes around the expected 60 Hz value as electrical loads were added or removed. A small display showed the readings, while LED indicators warned when the frequency crossed set thresholds.

The Arduino collects 800 readings per batch and sends them to Python over serial communication. Using NumPy and the Fast Fourier Transform (FFT), I analysed the signal’s frequency content and calculated a frequency estimate, then built a live Matplotlib display to track changes across successive measurements.

For the mechanical side, I designed an MDF case in SolidWorks to support 100 kg while staying within a weight limit. Structural analysis helped identify weak points, and an informal load test supported two adults with a combined weight of approximately 220 kg without failure.

Tools used: Arduino · ACS712 · Python · NumPy · Matplotlib · FFT · Serial communication · Display and LED indicators · SolidWorks · MDF fabrication
